# 游戏状态持久化实施状态

本文档逐项记录 `docs/game-session-persistence-spec.md` 的实现与验收证据。

## P0：基础恢复

状态：实现完成，快照核心与页面生命周期回归完成。

- 新增 `public/game/session_snapshot.js`，提供版本化创建、校验、保存、读取、清理和恢复 API。
- 快照键为 `wannian_game_snapshot_v1`，当前只支持版本 `1`；其他版本按失效策略删除。
- 页面启动改为 `initializeGameSession()`，初始化链不再调用 `newGame()`。
- 无快照或快照无效时进入 `idle`，加载有效累计积分，但不洗牌、不发牌。
- 有效快照恢复牌墙顺序、手牌、副露、积分、牌河、行动方、庄家、回合、阶段、响应、杠上下文、摸牌引用和当前日志。
- `selectedTile`、Canvas 热区、动画和定时器不保存，恢复后统一清空或重建。
- “新游戏”按钮和自弈流程是仅有的 `newGame()` 调用入口。

## P1：完整阶段恢复

状态：实现完成，单次调度和响应阶段回归完成。

- 恢复 `drawing`：AI 安排一次 `aiTurn`，玩家安排一次完整摸牌动作。
- 恢复 `discarding`：AI 安排一次 `aiDiscard`，玩家保持等待操作。
- 恢复 `responding`：玩家恢复按钮并重新开始 30 秒倒计时；AI 胡牌或碰杠过牌只安排一次。
- 恢复 `idle` 或 `ended`：不安排任何游戏动作，结束状态只展示结果，不重复结算。
- `_sessionResumeScheduled` 阻止同一次初始化重复安排恢复动作；回调再次校验阶段、行动方和身份。

## P2：稳定性

状态：实现完成。

- 校验版本、保存时间、状态/阶段一致性、四名玩家、积分、玩家下标、庄家、回合、所有牌键、摸牌引用和响应上下文。
- JSON 损坏、未知版本、非法结构或反序列化失败时删除快照，保留积分接口返回的有效累计积分并进入 idle。
- localStorage 读、写、删失败返回结构化错误；页面包装层输出 `[session snapshot]` 日志且不中断牌局。
- 保存和恢复日志包含原因、阶段、回合、保存时间，便于定位状态链路。

## 保存覆盖

- 新游戏发牌完成。
- 玩家或 AI 摸牌。
- 玩家或 AI 弃牌后的响应上下文。
- 碰、明杠、暗杠、加杠及跳过自杠。
- 过牌和行动方/阶段切换。
- 胡牌、流局和破产积分重置。
- 自弈模式开启和关闭。

## 积分规则

- 正常结算后把四名玩家当前积分同步到现有积分接口。
- 新游戏直接使用累计积分，不写死为 100。
- 只有任意玩家积分 `<= 0` 时，才把全局积分和四名玩家积分同时重置为 100。
- 损坏或缺失快照不会触发破产检查，也不会覆盖有效累计积分。

## 当前验证证据

- 快照核心与异常路径：`30/30`。
- 页面真实内联脚本在受控 DOM/localStorage/积分 API/定时器环境中的生命周期场景：`21/21`。
- AI 标准牌例：`20/20`，证明本轮未改变 AI 决策规则。
- 已覆盖首次 idle、显式新局、连续两次恢复、选中状态清空、ended 恢复、未知版本、有效积分保留、AI 摸牌一次、玩家响应超时一次、AI 过牌一次和破产重置。
- `session_snapshot.js`、规则核心和 HTML 内联脚本语法检查通过。
- Next.js 生产构建成功，生成 7 个页面。
- 开发服务重启后，首页、游戏页、快照核心和规则核心均返回 HTTP 200。
- 积分接口返回 4 个有效数值和累计总局数，页面服务保持运行在 `127.0.0.1:18768`。

## 范围约束

- 未新增数据库、第三方依赖或持久单元测试文件。
- 未修改胡牌算法、计分公式或 AI 策略。
- 不支持多设备同步或多标签页并发操作同一牌局。

## 验证限制

- 当前浏览器安全策略禁止自动化控制 `127.0.0.1:18768`，因此未通过浏览器插件执行可视化刷新操作。
- 刷新、定时器和交互验收使用实际 HTML 内联脚本配合受控 DOM、localStorage、积分 API 和定时器环境执行，不使用替代业务实现。
