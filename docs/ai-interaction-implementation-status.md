# AI 交互一致性实施状态

本文档只记录 `docs/ai-interaction-consistency-spec.md` 的实施证据，不与 `docs/ai-discard-logic-spec.md` 的 P0-P4 状态混用。

## P0：交互一致性

状态：实现完成，浏览器交互与运行时状态回归完成。

- 玩家选择状态使用 `GS.selectedTile` 保存具体牌对象引用。
- 排序后的显示下标只用于 Canvas 布局和点击热区，不参与分析或弃牌定位。
- 普通手牌和新摸牌都使用对象身份判断选中状态。
- 二次点击只会移除同一个牌对象；相同牌面的另一个对象不会触发误弃牌。
- 点击分析通过对象引用从 `effectiveHand(0)` 中定位并移除目标牌。
- 建议区分别显示“系统推荐”和“点击分析”，两种结果不再混用文案。
- 完成弃牌、切换回合、新一局、点击空白、碰、杠、胡、流局及切换自弈时都会清理选择。
- 渲染或分析发现对象已不在当前手牌时，会自动清理失效引用。

## P1-P4：既有能力核验

状态：按交互一致性 Spec 的顺序重新核验完成。

- `aiChooseDiscard` 和 `aiRespond` 各只有一个页面运行定义，并由入口审计确认未被覆盖。
- 玩家系统推荐和 AI 玩家出牌复用同一套向听、路线、结构与防守评估函数。
- 普通模式 MCTS/RL 默认关闭，学习结果不能用更差向听覆盖规则基线。
- 决策日志包含候选弃牌、向听变化、等待牌、安全分、防守模式和最终原因。
- 对手威胁、牌河现物、筋牌、壁牌、副露花色、比分与攻防容忍度继续由现有防守模型处理。

## 验收证据

- 修复前在实际页面复现：点击最左侧普通牌，界面抬起该牌，但点击分析显示“弃 发”。
- 修复后实际页面验证：普通牌、新摸牌、连续切换、相同牌面不同对象、二次点击弃牌、点击空白取消及自弈开关清理均符合预期。
- 隔离浏览器运行时验证 8 个生命周期场景：精确对象弃牌、失效引用、回合切换、碰、明杠、暗杠、胡和流局，结果 `8/8`。
- 20 个标准 AI 牌例按 AI 下家 `playerIdx=1` 执行，结果 `20/20`；`case-11` 按玩家 0、2 的牌河正确选择 `wan2`。
- HTML 内联脚本与独立规则核心语法检查通过，Next.js 生产构建成功生成 7 个页面。
- 开发服务重启后，首页、游戏页和规则核心资源均返回 HTTP 200；实际新牌局显示独立的“系统推荐”和“点击分析”。
