# P2 游戏记录导出设计

## 目标

用户点击“导出记录”时，服务端把当前游戏记录写入经批准的本地目录。每局记录使用稳定的 `gameSequence`，而不是日期或结算局数，文件名为 `万年麻将_第{gameSequence}局_{gameId}.json`。

## 数据流

1. `newGame()` 通过独立的本地序号槽原子分配正整数 `gameSequence`。
2. 当前游戏日志、快照和恢复状态均携带该序号；恢复不重新分配。
3. 页面将受限结构的记录和序号提交到 `POST /api/game/export`。
4. 服务端重新校验记录结构和顶层/记录内身份一致性，忽略且拒绝任何客户端路径字段。
5. 服务端只向显式配置、存在、可写且经批准的绝对目录写入。遇到同名文件时，依次使用 `_导出2`、`_导出3` 后缀；绝不覆盖已有文件。

## 安全边界

- `GAME_EXPORT_DIR` 必须为绝对存在目录；生产或强制批准模式下必须与 `APPROVED_GAME_EXPORT_DIR` 规范化后相同。
- 文件名只由受验证的局号与经过白名单清理的 `gameId` 构造；客户端不提供目录或文件路径。
- 写入在临时文件完成后以排他提交，冲突重新分配后缀；测试仅使用系统临时目录。
- 浏览器 Blob 下载不再是默认路径。仅当服务端导出失败时，经用户明确确认才能降级下载，且会说明它不能保证目标目录。

## 回归门禁

- 新局分配、快照恢复与重复导出保持同一局号。
- 同一局多次导出不覆盖。
- 相对路径、目录穿越、未批准目录、不可写目录和客户端路径字段都被拒绝。
- 结构无效记录被拒绝，合格记录只写入配置目录。
- 页面导出调用服务端，失败时才允许显式浏览器降级。
